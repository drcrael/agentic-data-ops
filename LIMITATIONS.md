# MVP limitations

- Discovery uses explicit Excel tables, blank boundaries, simple header/type signals and title/note heuristics. Nested visual layouts, multi-row headers, adjacent tables without separators, pivots and complex merged layouts may need source preparation. Inferred boundaries retain confidence and alternatives. Named ranges and validations are inspected but not automatically promoted into authoritative data contracts.
- Excel inspection uses one bounded in-memory openpyxl workbook. Default byte/cell limits intentionally refuse very large workbooks. CSV/TSV is UTF-8 with a fixed comma/tab delimiter and first-record header; arbitrary encodings and delimiters are not guessed.
- XLSM containers are readable; VBA semantics, external links and formula evaluation are out of scope. Formula results and spreadsheet errors are represented as unavailable, with explicit formula disclosure. Password-encrypted/corrupt workbooks fail.
- Statistical anomalies are review candidates. No authoritative real-world accuracy, coordinate frame, units, jurisdiction, ontology or formal sensitivity classification can be obtained from values alone.
- Relationship discovery is bounded and conservative: same canonical identifier names and compatible physical types, scalar joins and two-field candidate composite keys. Cross-name joins, composite foreign keys and fuzzy entity resolution require extensions. Profiling a sample does not establish population-wide uniqueness or orphan counts.
- All-null columns provide no observed type. Numeric strings in Excel retain their physical string distinction; CSV is interpreted lexically. Ambiguous slash dates are flagged rather than guessed. Type-sensitive equality may require an approved normalization step before joining differently encoded keys.
- Quality patterns come only from trusted configuration. Their length and nested repetition are limited; each match and complete rule evaluation have time budgets. Timeouts produce UNDETERMINED, not a false pass. No automatic destructive cleanup is performed.
- Human-authoritative answers are attributed to the supplied identity/authority, not verified against enterprise IAM. Risk acceptance is visible and expires, but external approval workflows, digital signatures and tamper-proof audit storage are not provided. Audit history is ordinary local JSON; named baselines have integrity hashes, not signed attestations.
- The persistent controller runs one conservative automatic pass per event and waits for new input. It supports CLI resolution/reassessment, not a daemon, scheduler, web UI or autonomous remediation executor. Mission/model/maturity-only changes reuse measurements; rule/governance changes reingest the bounded rows but reuse profiling. Source changes remeasure the workbook and conservatively reset authoritative answers. Per-cell incremental recomputation is not implemented.
- Removed fields/datasets retain complete histories in snapshots; resolved findings remain in the current inventory when their field references remain valid. Histories grow with the number of iterations; archival/compaction is not automatic.
- Baseline comparison detects schema, quality, semantic, governance, mission and AI-readiness changes and regressions. Explicit previously passing quality rules can flag contract-rule regression. Proposed-contract drift is tracked; enforcing an external schema-registry or industry-standard contract document is not implemented. Contracts deliberately remain proposed.
- Mission fitness needs explicit mappings and supported checks. Unstructured Mission Bible ingestion, arbitrary executable predicates and domain-specific mission simulation are not implemented. Freshness uses explicit quality rules; date-only/naive timestamps remain undetermined.
- The LLM gateway supports Ollama and OpenAI-compatible chat endpoints. Wire-format, retry, minimization and policy tests use controlled transports and mocks. No real downloaded model, GPU execution or commercial account was available/required for delivery verification. Provider-specific JSON-schema dialect restrictions may require `json_schema: false`.
- Local-only mode restricts the application's endpoints to literal loopback IPs and disables environment proxies and redirects. Administrators must ensure local servers do not forward inference remotely. Process-level isolation, network firewalls, classified-environment accreditation and supply-chain certification are deployment responsibilities.
- Model schemas/reference checks prevent fabricated provenance and authoritative property assignment. They cannot prove that every free-text explanation is semantically correct. Such explanations remain INFERRED and cannot control tools, policies, deterministic scores or lifecycle decisions.
- LLM caching is optional and in-memory per gateway instance. No persistent shared/distributed cache or cross-process semantic result reuse is supplied.
- Reports omit raw rows and common-value summaries by default, but names, aggregate statistics, extrema, source metadata and human answers may be sensitive. Keep output directories under appropriate access controls. Raw-value redaction/classification plugins are an extension point, not a completed DLP system.
- Linux is the verified platform. GitHub CI passed on Python 3.11–3.14; local measurements and the observed CI run are recorded in VALIDATION.md. Windows and macOS have not been validated end to end. The 100,000-row resource test targets Linux/macOS.

Extension points: implement `IngestionAdapter` for database/Parquet/JSON/Delta/Iceberg; translate explicit quality results to Great Expectations/Soda/dbt; export graph edges to Neo4j or graph RAG; integrate provenance/governance with Purview, OpenMetadata, DataHub or catalogs; add authenticated approval workflows, schema-registry enforcement, services and drift monitors without replacing the deterministic core.
