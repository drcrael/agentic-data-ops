# Delivery checklist

This checklist maps the supplied numbered specification to executable implementation and verification. IMPLEMENTED means functioning behavior is exercised, not merely that a class exists. PARTIALLY_IMPLEMENTED identifies a deliberate MVP boundary; details are in LIMITATIONS.md.

| Requirements | Status | Implementation | Verification / notes |
|---|---|---|---|
| 1–4: end-to-end assessment, evidence first, three knowledge states, separated architecture | IMPLEMENTED | `agents/orchestrator.py`, `models/`, `control/controller.py` | `tests/integration/test_pipeline.py`, `tests/acceptance/test_cli.py` |
| 5–7, 24, 52–54: package structure, typed canonical models, evidence, deterministic IDs and collisions | IMPLEMENTED | `models/core.py`, `models/assessment.py`, `models/control.py`, `util.py`, `evidence/store.py` | `tests/unit/test_models.py`, ingestion collision test. Models are grouped into three cohesive modules instead of one file per class; `physical_schema` avoids Pydantic's existing `schema` method name. |
| 8, 64, 90–91: graph and reference validation | IMPLEMENTED | `evidence/graph.py`, `evidence/validation.py`, `control/dependencies.py` | Security tests reject missing/duplicate evidence and dangling graph nodes; every emitted assessment passes integrity validation. Semantic concepts are represented by semantic-type assertions. |
| 9, 55: Excel inspection and region discovery | PARTIALLY_IMPLEMENTED | `ingestion/excel.py`, `ingestion/table_detection.py` | Semi-structured, hidden, named-range, validation, merged-title, formula, explicit-table, repeated-header and collision fixtures. Complex multi-row/visual layouts and automatic interpretation of named-range/validation semantics are not implemented. |
| 10–11, 45, 48, 56: deterministic profiling, physical types, hash, bounded sampling | IMPLEMENTED | `profiling/columns.py`, `profiling/statistics.py`, ingestion adapters | Exact counts, statistics, type-sensitive equality, deterministic reservoir sample, scan-limit disclosure, 100k-row performance test. Common values/enums require explicit opt-in. |
| 12–13, 75: keys, relationship candidates and orphan evidence | PARTIALLY_IMPLEMENTED | `profiling/keys.py`, `profiling/relationships.py` | Three expected relationships and exact orphan counts tested. Single-field relationships and two-field candidate keys; no composite foreign-key or differently named fuzzy join discovery. |
| 14–16, 57–59: quality dimensions, explicit rules, severity, anomalies | IMPLEMENTED | `profiling/quality.py`, `models/assessment.py` | Exact dirty counts, rule operators, explicit range violation versus potential outliers. Unsupported timeliness/integrity/domain expectations are explicitly UNDETERMINED. Severity factors retained. |
| 17–22, 60–63, 66: provider independence, routing, capabilities, structured retries and optional failure | IMPLEMENTED | `llm/`, `agents/` | Mock full integration, wire-format tests for Ollama and compatible providers, failed optional inference preserves measurements. Real-model execution is not claimed. |
| 19–20, 23, 69, 78–80, 102, 104: local-only, minimization, injection defense, no vendor coupling | IMPLEMENTED | `security/data_policy.py`, `llm/context.py`, gateway and versioned prompts | Actual outbound payload inspection; provider never called after denial; no redirects; malicious cells remain inert; external test network is blocked; regex timeout regression. |
| 25–27: targeted questions, attributed SME answers, governance | IMPLEMENTED | `agents/semantic.py`, `agents/governance.py`, `control/resolutions.py`, CLI `resolve` | Authoritative and non-authoritative answer tests, units propagation, uncertainty preserved, immutable snapshots. No enterprise identity verification. |
| 28–30, 105: explicit cumulative maturity and separate AI readiness | IMPLEMENTED | `maturity/`, packaged/configured criteria | Unknown criteria cannot pass; levels show satisfied/missing/next criteria and evidence. No LLM scoring. |
| 31–33, 99, 106: mission context and fitness by requirement | IMPLEMENTED | `mission/evaluator.py`, `examples/manufacturing_operations.yaml` | Clean identity can be FIT while units/frame remain UNDETERMINED. Explicit uniqueness/governance/rule/missing-field checks tested. Narrative-only requirements remain unresolved. |
| 34–37: prioritization, remediation, target schema, proposed contract | IMPLEMENTED | `agents/maturation.py`, `contracts/generator.py` | Explicit priority factors, dependencies, source field mapping, unresolved properties and rule origins; SME unit answer updates proposed schema. Candidate keys remain candidate proposals. |
| 38–40, 88–89: output artifacts, human report and run manifest | IMPLEMENTED | `reporting/writer.py` | All required files generated and canonical contents validated; atomic owner-only output bundles; manifest hashes. |
| 41–44, 81, 86: working CLI, no-LLM, config and reproducibility | IMPLEMENTED | `cli.py`, `config.py`, configurations | Installation, help, inspect, profile, analyze, mission, mock, no-LLM, resolve, prior and baseline workflows exercised. |
| 46–47, 65–66: logging and failure isolation | PARTIALLY_IMPLEMENTED | `logging.py`, orchestrator, gateway, CLI errors | Optional reasoning failures isolated per dataset/role, secrets excluded. Fatal input or deterministic integrity errors fail closed; the MVP does not publish partial workbook reports after a fatal ingestion/profiling defect. |
| 49–51: incremental implementation, package and code quality | IMPLEMENTED | `pyproject.toml`, source layout, local commits, static gates | Incremental unit/integration suites executed; Ruff and mypy required in CI. No production TODO/stub critical paths. |
| 67–68: caching and prompt versions | IMPLEMENTED | `LLMGateway.cache`, `prompts/*.v1.txt` | Cache hit and changed-evidence invalidation tested. Cache is optional/in-memory, not cross-process persistent. |
| 70–85, 87, 92–93, 103, 108: fixtures and meaningful tests | IMPLEMENTED | `scripts/generate_test_workbooks.py`, `tests/` | Clean, dirty, semi-structured, relational, manufacturing ambiguity, anomalies, injection, security, malformed/fabricated model output, no-LLM and mock acceptance. Actual counts/coverage are in VALIDATION.md. |
| 94–98, 100, 112: gates, demo, docs, configurations, generated examples | IMPLEMENTED | `scripts/test.sh`, `scripts/demo.sh`, README, configs, `examples/output/` | Gates and prescribed CLI execution performed. Example output is generated, not handcrafted. |
| 101: architectural boundaries | IMPLEMENTED | All source packages | Ingestion/profiling have no LLM dependency; agents use gateway; scoring stays deterministic; rendering does not calculate measurements. |
| 107: 100,000-row sanity check | IMPLEMENTED | `tests/acceptance/test_performance.py` | Full pipeline over streaming input; 100k source rows, 10k retained sample, bounded memory/time, scope disclosed. Measured resource results in VALIDATION.md. |
| 109–116: self-audit, limitations, extensions, delivery behavior | IMPLEMENTED | This file, LIMITATIONS, README, VALIDATION | Unfinished integrations and real-model verification are explicitly identified. No claim of enterprise accreditation. |
| 117.1–4: explicit controller, iterations, states and triggers | IMPLEMENTED | `models/control.py`, `control/controller.py` | Persistent iterations and source/SME/rule/config-trigger tests. FAILED is represented and fatal execution raises rather than serializing a successful run. |
| 117.5–7: fingerprinting, dependencies, selective reassessment and human gate | IMPLEMENTED | `control/dependencies.py`, controller, graph traversal | Resolution and rule-only tests assert profiler is not called; unresolved authority deterministically gates progress. Source changes remeasure the workbook. |
| 117.8–10: resolutions, promotion and finding lifecycle | IMPLEMENTED | `control/resolutions.py`, `control/history.py` | Supersession, attributed OBSERVED versus INFERRED knowledge, accepted risk, acknowledgement/planned states; snapshots preserve removed-field histories. |
| 117.11–16: remediation feedback, deltas and regression | PARTIALLY_IMPLEMENTED | `control/comparison.py`, `control/history.py` | Schema/quality/semantic/governance/mission/readiness comparisons and explicit-rule contract regression. External authoritative contract/schema-registry enforcement remains an extension. |
| 117.13–15, 17–18: convergence, risk, baselines and deterministic decisions | IMPLEMENTED | controller, resolution validation, baseline hash checks | Blocking gates, risk expiry, immutable names, named baseline selection and evidence comparison tested. User identities/authority are supplied rather than enterprise-authenticated. |
| 117.19–21: loop safety and audit log | IMPLEMENTED | controller, reporting, `assessment_history.json` | Conservative one automatic pass per explicit event; no repeated speculative reasoning. Persistent CLI feedback loop, not an autonomous daemon. `max_iterations` is a ceiling; the MVP uses an effective automatic budget of one. |
| Future enterprise connectors, graph database, web/API service, monitoring daemon, IAM | NOT_APPLICABLE | Documented extension interfaces | Explicitly optional in section 111; not represented as shipped capabilities. |
